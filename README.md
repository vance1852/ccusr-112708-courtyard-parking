# 临时开放停车场的分区收费与凭证交割

机关院落的分区车位探头、入口登记与收费联调。目录中的记录为本地合成联调资料。

- `data/site.json` 保存现场配置及设备消息各类型的字段顺序。
- `data/frames.jsonl` 保存不同设备和工作人员提交的消息，逐行解码。

`arrival` 是资料中的接收序号，`captured` 是来源记录的现场时刻，单位为秒。
`received` 是边缘收到消息的时刻，使用同一时间单位。设备补送仍携带原现场时刻。
`source` 表示消息来源，`type` 是消息名称，`args` 按现场配置列出的顺序给出原值。
每行记录一次接收，包括重复消息。设备此时的状态应按对应设备协议解释。

费率使用分每分钟。转区通道消息只给出当次车签和穿越方向。停车区探头能报单车位
或小组；有车状态属于实地占位。支付流水只在本岗亭持久唯一。计费按实际秒占一分钟
的比例计，累计应付在最终结算时四舍五入到分。

## 目录结构

```text
data/                  现场配置与设备帧（原始证据，不可变）
device_replay.py       逐帧读取原始联调消息
parking/
  events.py            按 wire_fields 把帧解码为具名事件
  schedule.py          费率政策时间线；入场时绑定费率承诺
  engine.py            事件溯源引擎：回放、占位推断、计费、凭证与交班
duty.py                岗亭值班 CLI（replay / dossier / handover）
tests/                 资料完整性测试与全部业务规则测试
```

## 运行

使用 Python 3.11 标准库即可，无需网络或外部设备。建议以隔离模式运行：

```bash
python3 -I device_replay.py                 # 逐帧输出原始消息
python3 -I duty.py replay                   # 回放并列出每张凭证及其证据链
python3 -I duty.py dossier P1               # 查一次停放：实际区段、收费、结算岗亭
python3 -I duty.py handover                 # 交班：未结停放与待核占位/费用
python3 -I duty.py replay --json            # 任一命令加 --json 输出结构化结果
python3 -I -m unittest discover -s tests -v
```

## 业务规则与落地方式

1. **通道穿越不等于停放。** `pass` 只证明车经过内院通道；实际停放区段只由
   探头 `spot` 占位证据建立（小组 `unknown` 只限缩到那一小片，不认车）。
2. **收费从可证实的付费停放开始。** 开放时段内登记、末尾才转入付费区的车，
   计费起点是第一份能认定到本车的付费区占位，而不是穿越时刻。
3. **费率承诺随入场绑定。** `price` 改价只约束改价后新登记的停放；在途停放
   （含从免费区转入收费区的访客）保留入场时承诺，直到当次停放结束。
4. **补送按发生时事实计。** 掉线期间补齐的消息按 `captured` 现场时刻落位，
   按当时区域事实与承诺计费，不按消息到达时的价格重算；到达顺序与现场顺序
   相反的证据标记 `evidence_out_of_order` 待核，不静默造区间。
5. **无确定付费区间先放行。** 出口挂两类待办并分开：`fee_pending`（费用待核）
   与 `occupancy_pending`（场内仍可能占位）。抬杆 `gate open` 不关闭占位，
   探头 `spot empty` 才确认驶离。
6. **收款须同时核对适用范围与授权。** 岗亭须持有本车有效 `payment_lease`
   且具备离线收款资格；无授权的收款不计入结算并记异常。`(岗亭, 流水)` 唯一，
   重复 `paid` 帧按一笔记账。已在另一岗亭结算的，再请求出口只开核对凭证、
   `collect_fen=0`，杜绝同段双收。
7. **更正只开差额凭证。** 补来的证据改变已结金额时，原结算/放行凭证与已合法
   放行的事实原样保留，另出 `adjustment` 凭证给出差额与当前净余额。
8. **全程可追溯。** 每张凭证的 `evidence` 都指回原始帧的
   `arrival/source/type/captured`；财务 `ask` 通过 `dossier` 一张链查到
   实际收了哪段、哪一岗亭成为结算依据；`handover` 把未结停放交给下一班次。
